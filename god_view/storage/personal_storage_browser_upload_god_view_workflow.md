# Personal Storage Browser Upload — God View

This workflow transfers one browser-selected object through the Zone Public Edge
after a personal storage transfer ticket has been issued. The browser never
receives storage credentials and never calls MinIO directly. Ticket issue is a
separate API boundary; this document starts with its output.

## API-scope contract

The input is an in-memory PUT request to the public URL returned by the
personal transfer-ticket API. The URL contains the bucket and encoded object
path selected by Zone Control. No /personal, /tenant or /me owner rewrite
happens on this data path. Authority is the one-time ticket, not a client
workspace or tenant header.

## Input and output

### Request headers

| Header | Use |
|---|---|
| Origin | Public Edge CORS allow-list. |
| X-Aurora-Transfer-Ticket | Opaque ticket id and secret. The only browser authority. |
| Content-Type | Same value bound into the ticket grant. |
| Content-Length | Browser-provided Blob length when available and checked when present. |
| traceparent | Transport correlation only. |

Cookies, Trinity headers, access keys, AWS Authorization, x-amz-* and client
workspace headers are not accepted as authority. Public Lua removes them
before the MinIO upstream.

### Request body

The body is the selected File stream. Its size was sent to Zone Control when
the ticket was requested. The object key is never inferred from an untrusted
public path after ticket issuance.

### Response

MinIO returns the normal S3 200 response and optional ETag. Public Edge does
not return the ticket, grant, or AWS signing material. CORS exposes only ETag,
Content-Length and Content-Type.

## Key and state contract

| Key | Read/write |
|---|---|
| AURORA_ZONE_TRANSFER/{ticket_id} | Public authorizer reads and CASes Issued to Consuming. |
| TransferTicketV1.public_path | Exact path match against Envoy :path. |
| TransferTicketV1.method | Must equal PUT. |
| TransferTicketV1.content_length | Must equal request content length when supplied. |
| TransferTicketV1.content_type | Must equal request Content-Type. |
| TransferTicketV1.expires_at_unix_seconds | Public authorizer rejects expired state. |

## Phase 1 — Browser → Zone Public Envoy → Public Authorizer

The browser sends the ticket header and file body directly to the public
hostname. Envoy matches the ticket header before the unauthenticated SDK
fallback route. The ext_authz request contains method, path and headers but
does not buffer the object body. This keeps streaming memory bounded.

~~~mermaid
sequenceDiagram
    participant B as Browser
    participant PE as Zone Public Envoy
    participant PA as Zone Public Authorizer
    participant TV as AURORA_ZONE_TRANSFER

    B->>PE: PUT public bucket path with ticket and file stream
    PE->>PE: CORS check and remove cookies AWS auth and untrusted headers
    PE->>PA: CheckRequest method path ticket headers
    PA->>TV: Read ticket by ticket id
    TV-->>PA: Issued ticket grant and expiry
    PA->>PA: Hash secret and compare method path size type Zone
    PA->>TV: CAS Issued to Consuming
    alt missing expired mismatched or already consumed
        PA-->>PE: Permission denied
        PE-->>B: 403 without MinIO request
    else valid ticket
        PA-->>PE: OkResponse audit headers and remove ticket header
        PE->>PE: Route public path to MinIO transfer cluster
        PE->>PE: Apply internal SigV4 signing
        PE->>MI: PUT rewritten bucket object path with stream
        MI-->>PE: S3 response
        PE-->>B: 200 and safe response headers
    end
~~~

The public authorizer never trusts a bucket or object path supplied in a
separate header. It compares the exact Envoy request path with the ticket
grant generated by Zone Control.

## Phase 2 — MinIO streaming and settlement

Public Envoy applies bounded connection buffers and a long stream idle timeout.
The upstream signing filter signs the rewritten MinIO request after route
selection. The browser ticket is removed before the upstream hop.

~~~mermaid
sequenceDiagram
    participant PE as Public Envoy
    participant SG as SigV4 signing filter
    participant MI as MinIO
    participant B as Browser

    PE->>SG: Authorized PUT request and stream
    SG->>SG: Rewrite host to MinIO and sign internal request
    SG->>MI: Signed PUT stream with bounded backpressure
    alt MinIO accepts
        MI-->>SG: 200 ETag
        SG-->>PE: Upstream response
        PE-->>B: 200 ETag Content-Type
    else MinIO rejects or stream fails
        MI-->>PE: 4xx or 5xx
        PE-->>B: S3 error without ticket material
    end
~~~

A successful transfer consumes the ticket before MinIO receives bytes. A
network failure after CAS therefore requires a new ticket and an application
retry decision; the same ticket cannot be replayed.

## Failure and recovery

| Failure | Boundary | Browser action |
|---|---|---|
| Ticket missing or invalid | Public authorizer | Request a new ticket. |
| Ticket expired or consumed | Public authorizer | Request a new ticket. |
| CORS preflight denied | Public Envoy | Fix allowed Console origin or deployment config. |
| MinIO 4xx | MinIO | Show object validation error; do not retry same ticket. |
| MinIO 5xx or network reset | Public Edge | Request a fresh ticket before retry. |
| Zone KV unavailable | Public authorizer | Retry later; fail closed. |
